# Скрипты сборки справочника

**К приложению не подключены.** Ничего отсюда не грузится в браузере, не
попадает в `CORE_ASSETS` в `sw.js` и не указывается в `index.html`. Это
инструменты сборки справочника, запускаются вручную.

Нужен только Python 3 (стандартная библиотека, зависимостей нет).

## Порядок сборки

```
python unfont.py --self-test                  # 1. проверить расшифровщик
python unfont.py --stats raw/lesson-*.txt     # 2. проверить транскрипцию
python unfont.py raw/lesson-*.txt -o ../lessons/   # 3. главы
python build_vocab.py                         # 4. data/vocabulary-by-lesson.json
python build_meta.py                          # 5. meta.json
python build_index.py                         # 6. ../INDEX.md
```

Шаги 4–6 читают то, что написали предыдущие, поэтому порядок важен.
Шаги 1 и 2 возвращают ненулевой код при ошибке — годятся для проверки в CI.

## Что откуда берётся

```
raw/lesson-NN.txt   <- пишется руками, единственный источник правды
   |  unfont.py
   v
../lessons/lesson-NN.md
   |  build_vocab.py            |  build_meta.py
   v                            v
../data/vocabulary-by-lesson.json   meta.json
                                     |  build_index.py  (+ vocabulary-by-lesson.json)
                                     v
                                  ../INDEX.md
```

Всё, что ниже `raw/`, — **производное**. Правки вносят в `raw/lesson-NN.txt`
и пересобирают; правка в собранном файле потеряется.

## unfont.py

Расшифровщик шрифтовой кодировки BWHEBB в Юникод. Ядро всего справочника;
как устроена кодировка и почему результат не нормализуется — в
[../restoration-report.md](../restoration-report.md).

```
python unfont.py raw/lesson-03.txt              # в stdout
python unfont.py raw/lesson-*.txt -o ../lessons/   # в файлы (.txt -> .md)
python unfont.py --self-test                    # 19 контрольных слов из книги
python unfont.py --audit raw/lesson-03.txt      # каждый отрезок: было, стало, брак
python unfont.py --stats raw/lesson-*.txt       # сводка по корпусу
```

Расшифровывается только то, что в угловых скобках `⟨…⟩` (U+27E8/U+27E9).
Эти символы выбраны потому, что не встречаются ни в русском тексте, ни в самой
кодировке. Без явной разметки «Qal», «sg.» и «BHS» были бы приняты за
еврейские слова.

**`--audit`** — главный инструмент проверки. Третья колонка — глифы, которых
нет в таблице; она должна быть пустой:

```
python unfont.py --audit raw/lesson-08.txt | grep "???"
```

Непустая колонка почти всегда означает опечатку в транскрипции (например,
кириллическую `а` вместо латинской), а не пробел в таблице. Как это выглядело
на практике — в отчёте.

**`--stats`** — та же проверка по всему корпусу сразу, плюс числа для отчёта.
Выходит с кодом 1, если найден хоть один неизвестный глиф.

## build_vocab.py

Собирает `../data/vocabulary-by-lesson.json` из разделов «Словарь N» / «Слова».

Читает **расшифрованные** главы, а не raw: в JSON тогда попадает ровно то, что
видно в справочнике. Из перевода вытаскивается число в скобках — частота слова
в еврейской Библии, её даёт само пособие.

```
python build_vocab.py           # пересобрать
python build_vocab.py --show    # показать разобранное и ничего не писать
```

Главы 1, 2 и 9 словаря не имеют в самом пособии; они помечены в тексте строкой
«*В этой главе словарного раздела нет.*», по ней выставляется `no_vocab: true`.
Пустой разбор в любой другой главе — ошибка, скрипт скажет об этом.

## build_meta.py

Собирает `meta.json` — компактную карту книги: `[номер, первая страница,
последняя страница, заглавие, [темы]]`. Строится из заголовков глав, руками
не пишется.

## build_index.py

Собирает `../INDEX.md` из `meta.json` и `../data/vocabulary-by-lesson.json`.
Правки прямо в `INDEX.md` теряются при следующей сборке.

## Вывод в консоль Windows

Все скрипты в начале делают `sys.stdout.reconfigure(encoding='utf-8')`.
Без этого печать еврейского текста падает с `UnicodeEncodeError` в консоли
cp1251. Убирать эту строку не нужно.
