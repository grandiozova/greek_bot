# Тесты

```bash
npm install     # один раз: ставит jsdom, единственную зависимость
npm test        # весь набор, ~20 секунд
npm run test:watch
```

Отдельный файл:

```bash
node --test tests/drills.test.js
node --test --test-name-pattern="поиск" tests/vocab.test.js
```

Само приложение зависимостей не имеет и по-прежнему открывается двойным
кликом по `index.html`. `package.json` существует только ради тестов.

## Как это устроено

`tests/helpers/app.js` поднимает приложение в jsdom. jsdom не ходит за
внешними файлами, поэтому каждый `<script src>` из `index.html` вклеивается
в разметку **отдельным** инлайновым тегом, в том же порядке.

Отдельным — принципиально. Классические скрипты делят одну глобальную
лексическую область: повторное `let allVocabCache` в другом файле — это
`SyntaxError`, и весь файл не грузится. Слей мы всё в один скрипт, тесты
перестали бы ловить как раз тот класс ошибок, из-за которого приложение
однажды не запускалось вовсе.

```js
const app = loadApp();              // { window, document, errors, get, … }
app.window.openLesson(4);           // function-объявления попадают в window
app.get('currentLessonPart');       // let/const — нет, их читаем через eval
assert.deepStrictEqual(app.errors, []);
app.close();
```

Полезное на `app`: `screen()`, `backButton()`, `appBarTitle()`, `fab()`,
`navActive()`, `msyms()`, `text(sel)`, `html(sel)`.

`loadApp` принимает `{ prefersDark, storage, breakScript }` — системная тема,
начальное содержимое `localStorage` и подмена файла битым кодом (для
самопроверки загрузчика).

**С пустым `localStorage` приложение стартует со экраном выбора курса** — так
и задумано (`app_default_course` не задан, значит спрашиваем). Перекрытие не
`.section`, поэтому `app.screen()` по-прежнему возвращает `mainMenu`, и старые
тесты от этого не изменились. Нужен конкретный курс без перекрытия — передайте
`storage: { app_default_course: 'greek' }`.

`tests/helpers/play.js` — драйвер, проходящий любое упражнение до конца. Он
не знает, что перед ним: жмёт варианты, печатает в поля, собирает фразы из
фишек и оценивает карточки, пока экран меняется. Поэтому один и тот же код
прогоняет упражнения урока, тест и обе колоды карточек.

## Подводные камни

- **Другой realm.** Массивы и объекты из `app.get(…)` приходят из окна jsdom,
  и `assert.deepStrictEqual` придирается к прототипу при одинаковом
  содержимом. Сравнивайте длину, свойство или строку — либо просите сам
  `eval` вернуть готовую строку через `.join(', ')`.
- **Таймеры.** После ответа приложение ждёт ~1.2 с и переходит к следующему
  вопросу. `playThrough` подменяет `scheduleAdvance` на мгновенный —
  точечно, потому что тесты про подсветку правильного варианта смотрят как
  раз на экран обратной связи. Нужен тот же приём вручную —
  `withInstantAdvance(app, fn)`.
- **`errors` надо проверять.** Ошибка в скрипте не роняет тест сама по себе.
  Виртуальная консоль подключается до разбора документа (иначе всё, что
  упало при загрузке, теряется), а тест обязан сам заглянуть в `app.errors`.
  Что эта проводка жива, проверяет тест «самопроверка загрузчика».
- **`app.close()`** в конце теста — иначе окна jsdom копятся.

## Чего эти тесты не проверяют

Дальше только руками или отдельной оснасткой:

- **Вид.** jsdom не считает layout: горизонтальную прокрутку, наползание
  элементов и реальные размеры видно только в браузере.
- **Контрастность** тем — считается по токенам из `styles/tokens.css`,
  отдельной проверки пока нет.
- **Офлайн.** `static.test.js` следит за полнотой `CORE_ASSETS`, но сам
  сервис-воркер не запускается: холодный старт без сети проверяется руками
  по чек-листу в `AGENTS.md`.
- **Шрифты и лигатуры.** Тест сверяет имена иконок со списком `icon_names=`,
  но не то, как они рисуются.
